# End-to-end demo

The demo shows the whole lifecycle of an IO schema with GA4GH APIs: a WDL
workflow and its IO schema are registered in
[TRS-Filer](https://github.com/elixir-cloud-aai/trs-filer), a client builds a
form from the schema, and the values that a user enters become a WES run on
[Conquest](https://github.com/anuragxxd/conquest), whose outputs are
normalised by the schema. The user never chooses a workflow type, a WES
endpoint or engine parameters.

**Experimental:** the demo follows version 0.3 of the profile, which may
still change, and depends on servers outside this repository (see [Known
limits](#known-limits)).

## The demo files

Everything is in
[`examples/demo/`](https://github.com/uniqueg/ga4gh-io-schema/tree/main/examples/demo):

| File | What it is |
| --- | --- |
| `demo.wdl` | The workflow (WDL 1.1): filters aligned reads by mapping quality and flags, sorts and indexes them with samtools, and writes an HTML report. |
| `ga4gh-io.schema.json` | Its IO schema, generated by `build_schema.py`. |
| `schema.overlay.json` | What the schema adds to the output of [`convert wdl`](../tools/convert-wdl.md), as a JSON Merge Patch. |
| `build_schema.py` | Regenerates the schema (`--check` fails if the checked-in schema is outdated; the tests run it). |
| `values.json` | Input values for a run, with public `https` test data. |
| `register.py` | Registers the workflow and its schema in TRS-Filer. |
| `conquest.py` | Adds Conquest's engine parameters to a run request, submits it, waits for the run and normalises its outputs. |
| `demo_http.py` | JSON over HTTP for the scripts (standard library only). |
| `expected/` | A run log as Conquest reports it, and the normalised outputs of it. |
| `data/test.paired_end.bam` | A copy of the test data, for runs without network access. |

The inputs and outputs of the workflow:

| Parameter | In the form | Notes |
| --- | --- | --- |
| `reads` (input) | "Aligned reads (BAM)", a file reference (`https` or `s3`) | Required; an example value is given. |
| `min_mapq` (input) | "Minimum mapping quality", a slider from 0 to 60 | Default 0; a value out of range gets the message of `x-ga4gh-error-message`. |
| `read_filter` (input) | "Read filter", a choice of `none`, `proper_pairs` and `primary_only` | Default `none`. |
| `filtered_bam` (output) | "Filtered reads (BAM)" | The filtered reads, sorted by coordinate. |
| `filtered_bam_index` (output) | "Index of the filtered reads (BAI)" | Its own output, see [Known limits](#known-limits). |
| `report` (output) | "Alignment report (HTML)", shown with `html-viewer` | `text/html`; clients show it sandboxed (see [Rendering schemas and outputs](../security.md#rendering-schemas-and-outputs)). |

The test data is `test.paired_end.bam` of
[nf-core/test-datasets](https://github.com/nf-core/test-datasets) (MIT
licence), 200 reads of SARS-CoV-2, pinned to a commit of that repository;
the samtools image is `quay.io/biocontainers/samtools:1.24--h9dcdb79_1`.

## Prerequisites

- **This package**, with the WDL extra, in a checkout of this repository:
  `pip install -e ".[wdl]"`. The scripts need nothing else.
- **A commit of this repository that contains the demo**, as a full commit
  SHA (40 hex digits). Conquest runs workflows from a GitHub repository at a
  commit; the URL of the primary descriptor in TRS is pinned to it too. The
  registered files are read from the checkout, so run the scripts in a
  checkout of that commit (e.g., `git rev-parse HEAD` after the commit is
  pushed). The scripts use this repository's URL; `--repository` names
  another one (e.g., a fork).
- **TRS-Filer** with I/O Schema support (see [I/O
  Schemas](https://trs-filer.readthedocs.io/en/latest/io-schema/) in its
  documentation), and an access token that may write tools, in the
  environment variable `TRS_TOKEN` (sent over `https` only). If TRS-Filer
  validates tool classes, the tool class `workflow` must exist. With `custom.io_schema.validation`,
  TRS-Filer also checks the schema when it's registered.
- **Conquest** with WDL 1.1, able to fetch from `github.com`, the test data
  over `https`, and the samtools image. If it checks tokens, the token is in
  the environment variable `WES_TOKEN` (sent over `https` only).
- **For the portal part:** a portal that renders forms from IO schemas, finds
  TRS-Filer and Conquest (e.g., in a service registry), and builds run
  requests with Conquest's engine parameters, such as Krini with the form of
  ELIXIR Cloud Components. These are under development; until they are
  deployed, the [command-line path](#2-run-it-from-the-command-line) is the demo.

The commands below are for Bash; set the URLs of the deployments first:

```bash
export TRS_URL=https://trs.example.org/ga4gh/trs/v2
export WES_URL=https://conquest.example.org/ga4gh/wes/v1
export SHA=$(git rev-parse HEAD)
```

## 1. Register the workflow

```bash
python examples/demo/register.py --trs-url "$TRS_URL" --revision "$SHA"
```

The script creates the tool `ga4gh-io-schema-demo` with the version `1.0.0`
(`PUT /tools/ga4gh-io-schema-demo`: the schema names both in
`x-ga4gh-workflow`, so they are chosen, not generated), and prints the URL of
the schema in TRS:

```text
https://trs.example.org/ga4gh/trs/v2/tools/ga4gh-io-schema-demo/versions/1.0.0/WDL/descriptor/ga4gh-io.schema.json
```

The version has, for the descriptor type `WDL`, as the [TRS
convention](trs.md#publishing-convention) says:

- the primary descriptor `demo.wdl` (`PRIMARY_DESCRIPTOR`), with its content,
  its SHA-256 checksum and a URL pinned to the commit
  (`https://raw.githubusercontent.com/uniqueg/ga4gh-io-schema/<SHA>/examples/demo/demo.wdl`);
- the IO schema, of type `OTHER` at the path `ga4gh-io.schema.json` next to
  it, with its content and checksum.

`--dry-run` prints the registration (the body of the `PUT` request) and
sends nothing. Check the result as a client would (see [Discovery by
clients](trs.md#discovery-by-clients)):

```bash
curl "$TRS_URL/tools/ga4gh-io-schema-demo/versions/1.0.0/WDL/files"
curl "$TRS_URL/tools/ga4gh-io-schema-demo/versions/1.0.0/WDL/descriptor/ga4gh-io.schema.json"
```

The first lists `ga4gh-io.schema.json` (`OTHER`) next to `demo.wdl`
(`PRIMARY_DESCRIPTOR`); the second returns the schema in `content`.

## 2. Run it from the command line

The same run without a portal, step by step, from the values file to the
normalised outputs.

1. Translate the values into a run request (see
   [`wes-params`](../tools/wes-params.md)); Conquest takes the GitHub
   repository as `workflow_url`, and stages `https` and `s3` inputs:

    ```bash
    ga4gh-io-schema wes-params --schema examples/demo/ga4gh-io.schema.json \
      --values examples/demo/values.json --allow-scheme https --allow-scheme s3 \
      --request --workflow-url https://github.com/uniqueg/ga4gh-io-schema \
      > request.json
    ```

2. Add Conquest's engine parameters (the commit and the main workflow file):

    ```bash
    python examples/demo/conquest.py request request.json --revision "$SHA" \
      > conquest-request.json
    ```

    The request is then:

    ```json
    {
      "workflow_params": {
        "io_schema_demo.reads": "https://raw.githubusercontent.com/nf-core/test-datasets/3e548a3b34994380db1602506e0721fadbad6de1/data/genomics/sarscov2/illumina/bam/test.paired_end.bam",
        "io_schema_demo.min_mapq": 20,
        "io_schema_demo.read_filter": "proper_pairs"
      },
      "workflow_type": "WDL",
      "workflow_type_version": "1.1",
      "workflow_url": "https://github.com/uniqueg/ga4gh-io-schema",
      "workflow_engine_parameters": {
        "revision": "<SHA>",
        "main_workflow_path": "examples/demo/demo.wdl"
      }
    }
    ```

3. Submit it (`POST /runs`, as JSON); the script prints the run ID:

    ```bash
    RUN_ID=$(python examples/demo/conquest.py submit conquest-request.json --wes-url "$WES_URL")
    ```

4. Wait until the run has ended; the script checks the state every 10
   seconds (`--interval`), for up to an hour (`--timeout`), and writes the
   `RunLog`:

    ```bash
    python examples/demo/conquest.py wait "$RUN_ID" --wes-url "$WES_URL" > run-log.json
    ```

5. Normalise the outputs (see [Output normaliser](../tools/outputs.md)):

    ```bash
    ga4gh-io-schema outputs --schema examples/demo/ga4gh-io.schema.json --run-log run-log.json
    ```

For the run log in `expected/run-log.json`, in the shape that Conquest
reports (outputs keyed by the names of the WDL outputs, qualified with the
workflow name, as `s3://` URIs in its bucket), the result is:

```json
--8<-- "examples/demo/expected/outputs.json"
```

`conquest.py run` does all of it in one command (with `--dry-run`, it prints
the request of step 2 and stops):

```bash
python examples/demo/conquest.py run --revision "$SHA" --wes-url "$WES_URL"
```

If the run ends in another state than `COMPLETE`, `run` prints the partial
outputs (`"conformance": "partial"`) and exits with status 1.

`wes-params` stays server-neutral: the engine parameters, and the GitHub
repository in place of a TRS URL, are what Conquest needs today; a WES server
that resolves TRS URLs needs neither.

## 3. Run it from a portal

Once a portal as described in [Prerequisites](#prerequisites) is deployed
(e.g., Krini with the I/O Schema form, still under development):

1. Log in and choose to run a workflow; pick "I/O Schema demo". Expected: a
   form with the titled fields of the table above: a file reference for the
   reads, a slider for the mapping quality, a choice of read filters; no
   workflow type, no WES URL, no JSON editor.
2. Enter a mapping quality of 61 (e.g., in a text field, if the slider
   doesn't allow it). Expected: the error "The minimum mapping quality is a
   whole number from 0 to 60" next to the field; nothing is sent.
3. Enter the values of `values.json` and submit. Expected: the run moves from
   `QUEUED` through `RUNNING` to `COMPLETE`.
4. Open the outputs. Expected: the three outputs with their titles; the
   report in a sandboxed viewer. Conquest gives `s3://` URIs, which a browser
   can download only through a gateway or presigned URLs (see [Known
   limits](#known-limits)).

## Running the workflow locally

Without TRS-Filer and Conquest, miniwdl (installed with the `wdl` extra) runs
the workflow with Docker, on the local copy of the test data:

```bash
miniwdl run examples/demo/demo.wdl reads=examples/demo/data/test.paired_end.bam \
  min_mapq=20 read_filter=proper_pairs
```

It writes `outputs.json` with the local paths of the outputs, keyed by the
qualified names as above; the report says that 192 of the 200 reads are left.
miniwdl initialises Docker swarm mode on the first run, if it is off (`docker
swarm leave --force` turns it off again).

## Changing the workflow

`ga4gh-io.schema.json` is generated: change `demo.wdl` or
`schema.overlay.json`, then run

```bash
python examples/demo/build_schema.py
```

The overlay adds what WDL can't express and the converter leaves to the
author: the TRS identifiers and the path of the primary descriptor, the
bounds and error message of `min_mapq`, widgets, format terms (EDAM) and the
media type of the report, and an example value. The tests fail if the
checked-in schema differs from what the script writes, and the checksum in
`x-ga4gh-workflow` changes with every change of `demo.wdl`. Then raise
`trs_version_id` in the overlay too, and register the new version from a new
commit: `register.py` replaces the whole tool (`PUT`) with that one version,
and clients that fetched the old version must not get another workflow under
its identifier.

## Known limits

- **Secondary files:** WDL has no secondary files, so the index of the
  filtered reads is an output of its own (`filtered_bam_index`), not a
  `secondaryFiles` pattern of `filtered_bam` (see [Mapping to workflow
  languages](../specification/files.md#mapping-to-workflow-languages)).
  miniwdl, and so Conquest, put each output in a directory of its own, so the
  index doesn't lie next to the reads, and a pattern would be wrong.
- **Conquest runs from GitHub only:** it needs the repository URL, a full
  commit SHA and the main workflow path, not a TRS URL; clients add them
  (here, `conquest.py`). The URL of the primary descriptor in TRS is pinned to
  the same commit, but nothing checks that the two match, besides the checksum
  in the schema.
- **Outputs on Conquest** are `s3://` URIs in its bucket; browsers can't
  download them without a gateway or presigned URLs. Conquest reports outputs
  by name for WDL only.
- **Authentication:** Conquest doesn't check tokens yet; a public deployment
  lets anyone start runs. Use a deployment that isn't public.
- **Cross-origin requests:** a portal in a browser needs CORS on TRS-Filer and
  Conquest.
- **Not verified end to end:** the scripts are tested against a mock server
  only, and `expected/run-log.json` is written from Conquest's source code,
  not recorded from a run; the workflow itself has run with miniwdl locally.
